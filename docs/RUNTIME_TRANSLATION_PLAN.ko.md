# 이미지 외 텍스트 번역 경로

## 목표와 기준

특정 게임의 이름·대사·맵 번호로 동작을 분기하지 않는 공통 도구를 구현한다. 작업 기록은 게임 내용 없이 수치와 검증 범위만 남긴다.

대사·이름·선택지·메뉴·플러그인 UI와 실행 중 생성된 문구를 대상으로 한다. 이미지의 글자와 Vertex AI는 이번 범위에서 제외한다. 기존 기능·버튼은 유지한다.

정적 캐시 적중만으로 완료 처리하지 않는다. 캐시에 없는 새 문장이 실제 게임에서 수집되고, 로컬 번역을 거쳐 같은 화면에 정상 표시되는 경우까지 검증한다.

## 데이터 흐름

```text
게임 텍스트 후크
   | 캐시 적중 ----------------------------> 기존 그리기 경로
   |
   + 미번역 원문 -> 로컬 파일 요청함 -> Rust 작업자 -> 기존 배치 검증/DB
                                      |                 |
                                      +-- 로컬 모델 <---+
                                             |
응답 파일 <- 검증된 번역 <--------------------+
   |
   + 항목·표면 세대 확인 -> 배경 복구 -> 번역 표시
```

게임과 Rust 작업자는 생성된 프로젝트 산출물 안의 파일 요청함을 사용한다. 새 HTTP 수신 서버와 게임 내 제공자 인증 처리를 추가하지 않는다. 파일명은 캐시 키의 해시로 제한하고 원문 크기·스키마·언어·엔진을 검사한다. 게임 원본 데이터는 수정하지 않는다.

동일 원문 요청은 합치며, 검증된 번역을 DB와 응답 파일에 저장한다. 작업자가 없거나 번역에 실패한 상태는 진단에 남긴다. 실패를 번역 성공으로 기록하지 않는다.

## 구현 순서

1. 요청·응답 계약과 Rust 처리: 제어문자 보존, DB 재사용, 프로젝트 범위와 재시도 검증.
2. 게임 요청함 클라이언트: 중복 방지, 비동기 파일 I/O, 오류·중단·재시작 검증.
3. 어댑터의 비동기 표시: 메시지·창·비트맵·스프라이트·PIXI 각각의 수명과 표면 세대 검사.
4. 직접 Canvas·DOM 텍스트의 관찰과 중복 방지. 이미지에는 적용하지 않는다.
5. 앱/CLI 작업자 제어와 진단. 기존 사전 번역·검수·내보내기·설치·복구 유지.
6. 실제 게임에서 캐시를 비운 문장·플러그인 버튼·선택지·이름·화면 전환을 재현한다.

## 테스트 범위

```text
원문 -> 요청 검증 -> 코덱 -> 배치 응답 검증 -> DB -> 응답 파일
        | 잘못된 키/경로       | 코드 손실/503       | 재시작/중복
        v                     v                    v
      명시적 거부          실패/재시도           기존 결과 재사용

표시 -> 캐시 적중 / 지연 응답 / 창 교체 / 폐기 / 가려짐 / 내용 변경
        모든 어댑터에 대해 원문 보존·중복 그리기·오래된 응답 적용 여부 확인
```

대기 중에는 게임 프레임을 막지 않는다. 번역이 도착했더라도 원래 창이나 문장이 바뀌었으면 적용하지 않는다. 요청·응답 실패는 영구 성공 캐시에 넣지 않는다.

## 구조 검토

- 기존 코덱·배치 검증·DB 저장을 재사용하고 게임 쪽은 텍스트 후크와 표시만 담당한다.
- 정적 파일 추출에만 의존하지 않아 동적으로 생성된 문장도 관찰할 수 있게 한다.
- 파일 요청함은 데스크톱 게임 실행 환경을 대상으로 한다. 브라우저 단독 배포는 별도 연결 방식이 필요하다.
- 정적 분석 후보, 실행 중 관찰한 텍스트, 실제 번역·표시 성공을 서로 다른 근거로 기록한다.
- 이 환경에 필요한 독립 Plan 검토 도구가 없어 독립 검토 완료로 기록하지 않는다.
