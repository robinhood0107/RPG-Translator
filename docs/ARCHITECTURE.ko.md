# 코드 구조와 유지보수

## 작업 흐름

게임 선택 → 스캔 → 로컬 서버 배치 번역 → 검수 → 정적 캐시 내보내기 → 게임 설치 → 복구 순서로 동작한다.

- `crates/core/src/scanner.rs`: 엔진 감지와 JSON 추출. 원문 위치와 연속 대사 블록을 보존한다.
- `crates/core/src/db.rs`: 마이그레이션·원문·출현 위치·번역·검수 상태의 저장소.
- `crates/core/src/batch.rs`: 중복 제거, 입력 분할, 응답 검증, 재시도와 중단·재개.
- `crates/core/src/provider.rs`: 모델 탐색과 로컬 제공자 요청. 응답의 게임 문법 검증은 배치 계층에 둔다.
- `crates/core/src/export.rs`: 승인 상태의 번역과 별칭 키를 런타임 번들로 변환한다.
- `crates/core/src/install.rs`: 파일 해시를 기록하고 복구 전에 변조·경로 이탈을 검사한다.

## 데스크톱 경계

`apps/desktop/src/api.ts`가 프런트엔드와 Tauri 명령의 계약이다. 실제 파일·DB 작업은 `src-tauri/src/commands/`에서 코어로 전달한다. 명령 추가 시 Rust 등록부, 요청·응답 타입, API 매핑과 호출 화면을 함께 확인한다.

`App.tsx`는 프로젝트 선택, 작업 진행과 검수 초안의 상태를 소유한다. 작업 완료 후 저장 상태를 다시 읽으며, 실행 중에는 충돌하는 쓰기 작업을 막는다. 아직 상태와 작업 패널이 큰 파일에 모여 있어, 추가 분리는 기존 회귀 테스트를 유지하며 진행한다.

표시 문구는 `ui/labels.ts`, 상단 메뉴는 `ui/DesktopChrome.tsx`, 테마 저장은 `ui/useTheme.ts`에 둔다. `ui/themes.css`의 색상 토큰은 포털 메뉴와 대화상자에도 적용된다. 새 색상을 직접 패널에 넣지 말고 두 모드의 토큰과 대비를 함께 확인한다.

## 런타임 경계

현재 런타임은 캐시 조회 방식이다. 없는 번역은 원문을 유지하며, 게임 실행 중 제공자를 호출하지 않는다. 실행 중 번역은 별도 후속 작업이다.

`RPGTranslator.js` → `runtime/boot.js`가 로딩 순서와 정적 번들을 검사한 뒤 어댑터를 설치한다. `runtime/text-orchestrator/`는 관찰 항목, 소유권, 구독과 그리기 세대를 조정한다.

- 메시지 어댑터: 완성된 대사 블록과 창 생명주기.
- 창 어댑터: `drawText`·`drawTextEx`와 배경·후속 그래픽 재생.
- 비트맵 어댑터: 직접 그려지는 텍스트의 대체 처리.
- 스프라이트·PIXI 어댑터: 내용·스타일·부모·가시성 변경.

창이 전체 문자열을 처리하는 동안에는 하위 비트맵이 같은 문자열을 다시 번역하지 않는다. 원문의 짧은 폭에 번역문이 압축되고 상위 레이어가 다시 그리는 문제를 막는 경계다. 창을 교체·폐기하면 이전 세대의 그리기 명령과 구독도 적용되지 않아야 한다.

이미지에 이미 포함된 글자와 플러그인이 동적으로 만드는 모든 문장이 자동 지원되는 것은 아니다. 추출 누락, 캐시 미스, 후킹 누락, 이미지 글자를 구분해 진단한다.

## 변경 검증

- 코어·명령 변경: `cargo test --workspace`, `cargo fmt --check`.
- 런타임 변경: `node --test runtime/overlay-plugin/tests/runtime-overlay.test.js`와 실제 게임 사본의 같은 화면 전후 비교.
- 화면 변경: `npm --prefix apps/desktop test`, `npm --prefix apps/desktop run web:build`, 두 테마의 실행 화면 확인.
- 설치 변경: 설치 전 원본 해시 기록 → 설치 → 실행 → 복구 → 해시 일치 확인.

소스 정적 분석과 단위 테스트는 전체 게임 진행의 모든 분기를 실행했다는 증거가 아니다. 실제 관찰한 화면과 아직 실행하지 않은 상태를 검증 기록에서 구분한다.
